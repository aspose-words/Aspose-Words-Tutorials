# Как конвертировать docx в markdown с изображениями в подпапке

Если вам нужно **конвертировать docx в markdown**, при этом аккуратно упорядочить каждое встроенное изображение, вы попали в нужное место. Многие разработчики программно генерируют отчёты, руководства или черновики блогов и в итоге получают хаотичную смесь файлов изображений, разбросанных по каталогу вывода. В этом руководстве показан чистый, основанный на обратных вызовах подход с использованием Aspose.Words для .NET, который экспортирует документ в markdown, сохраняет каждое изображение в отдельную папку *md‑resources* и сохраняет готовый markdown‑файл, готовый к публикации.

> **Быстрый обзор:**  
> • Настройте `MarkdownSaveOptions`  
> • Реализуйте `IResourceSavingCallback` для перенаправления изображений  
> • Вызовите `Document.Save` с настроенными параметрами  

Теперь, когда вы понимаете, почему обратный вызов предпочтительнее пост‑обработки, давайте перейдём к пошаговому решению.

## Быстрые ответы
- **Что делает «конвертировать docx в markdown» на самом деле?** Она преобразует разметку Word в обычный текст markdown, сохраняя заголовки, списки, таблицы и ссылки на изображения.  
- **Какая библиотека выполняет конвертацию?** Aspose.Words for .NET предоставляет полностью управляемый серверный API, работающий без установленного Microsoft Word.  
- **Нужно ли писать какой‑либо код обработки изображений?** Нет; `IResourceSavingCallback` заботится о сохранении каждого изображения в указанную папку.  
- **Можно ли изменить имя папки вывода?** Конечно — замените `"md-resources/"` на любой желаемый относительный или абсолютный путь.  
- **Совместимо ли решение с .NET 6 и более новыми версиями?** Да, оно работает на .NET 6+, .NET 5, .NET Core 3.1 и .NET Framework 4.7+.

## Что такое конвертировать docx в markdown?
**Convert docx to markdown** — это процесс взятия документа Microsoft Word (DOCX) и создания markdown‑файла (`.md`), представляющего тот же контент с использованием синтаксиса markdown. Конвертация сохраняет структурные элементы и при желании извлекает встроенные ресурсы, такие как изображения.

Конвертацию выполняет Aspose.Words, библиотека, поддерживающая **более 35 форматов ввода и вывода** — включая DOCX, PDF, HTML и Markdown — что позволяет работать с документами в сотни страниц без загрузки всего файла в память.

## Почему использовать Aspose.Words для экспорта в markdown?
Aspose.Words обрабатывает документы в памяти и записывает результат непосредственно в целевой формат, что означает:

Aspose.Words обеспечивает высокопроизводительную, точную конвертацию, предоставляя полный контроль над обработкой ресурсов. Это устраняет необходимость в пост‑обработке, снижает использование памяти и гарантирует, что изображения, таблицы и стили точно воспроизводятся в markdown‑выводе.

- **Скорость:** Обычные DOCX‑файлы объёмом 200 страниц конвертируются в markdown менее чем за 2 секунды на стандартной ВМ.  
- **Точность:** Поддерживаются все более 50 встроенных вариантов markdown, обеспечивая корректное отображение таблиц, блоков кода и сносок.  
- **Контроль ресурсов:** Встроенный `IResourceSavingCallback` позволяет точно указать, куда сохранять каждое изображение, исключая необходимость отдельного шага очистки.

## Как конвертировать docx в markdown? 

Загрузите исходный документ с помощью `new Document("source.docx")`, настройте `MarkdownSaveOptions` для использования обратного вызова, который сохраняет каждое изображение в `md-resources/`, а затем вызовите `doc.Save("output.md", saveOptions)`. Этот трёхшаговый шаблон конвертирует файл, извлекает изображения и создаёт чистый markdown‑файл с относительными ссылками на изображения — всё в одном вызове метода.

### Шаг 1: настройка параметров сохранения для конвертации в markdown

MarkdownSaveOptions задаёт, как Aspose.Words конвертирует документ в Markdown.

```csharp
// Step 1: Initialize Markdown save options
var markdownSaveOptions = new Aspose.Words.Saving.MarkdownSaveOptions();
```

```csharp
// Step 1: Initialize Markdown save options
var markdownSaveOptions = new Aspose.Words.Saving.MarkdownSaveOptions();
```

> **Почему это важно:**  
> Если явно не создать `MarkdownSaveOptions`, библиотека использует настройки по умолчанию, которые встраивают изображения непосредственно в файл Markdown в виде строк Base64. Это делает файл огромным и сводит на нет цель иметь чистую папку *images*.

### Шаг 2: определение обратного вызова сохранения ресурсов для экспорта изображений

`IResourceSavingCallback` позволяет контролировать, куда сохраняется каждый ресурс (изображение, SVG) во время экспорта.

Теперь мы указываем сохраняющему модулю **куда** помещать каждое изображение. Интерфейс `IResourceSavingCallback` предоставляет точку входа, которая срабатывает для каждого найденного ресурса (изображения, SVG и т.д.) во время экспорта. Внутри обратного вызова мы:

1. Убеждаемся, что целевая папка существует (`md-resources/`).  
2. Устанавливаем `OutputFileName` в путь к папке плюс оригинальное имя ресурса.  

```csharp
// Step 2: Hook into the resource‑saving pipeline
markdownSaveOptions.ResourceSavingCallback = new Aspose.Words.Saving.IResourceSavingCallback(
    (args) =>
    {
        // All images will be placed in "md-resources" relative to the output .md file
        const string folder = "md-resources/";
        Directory.CreateDirectory(folder);          // Create folder if it doesn’t exist

        // Preserve the original file name (e.g., image001.png) but prepend the folder path
        args.OutputFileName = Path.Combine(folder, args.ResourceFileName);

        // Optional: you could also change the format here (e.g., convert BMP to PNG)
        // args.ResourceFileName = Path.ChangeExtension(args.ResourceFileName, ".png");
    });
```

> **Распространённый вопрос:** *Что если я хочу встраивать изображения вместо их сохранения?*  
> Просто пропустите обратный вызов или установите `args.OutputFileName = null;` — сохраняющий модуль автоматически встроит изображение как строку Base64.

> **Особый случай:** В некоторых старых документах встречаются дублирующиеся имена изображений. Приведённый выше обратный вызов перезапишет предыдущий файл. Чтобы избежать этого, можно добавить GUID:

```csharp
args.OutputFileName = Path.Combine(folder,
    $"{Path.GetFileNameWithoutExtension(args.ResourceFileName)}_{Guid.NewGuid()}{Path.GetExtension(args.ResourceFileName)}");
```

### Шаг 3: сохранить документ как markdown и проверить результат

После полной настройки параметров окончательный вызов — однострочная команда, которая записывает файл Markdown и связанные с ним изображения на диск.

```csharp
// Step 3: Perform the actual export
string outputPath = @"C:\Exports\MyReport.md";
doc.Save(outputPath, markdownSaveOptions);
```

Если всё прошло успешно, вы увидите:

- `MyReport.md` — markdown‑представление вашего исходного документа.  
- `md-resources/` — папка рядом с файлом `.md`, содержащая все извлечённые изображения (например, `image001.png`, `image002.jpg`).  

**Пример фрагмента markdown** (автогенерировано Aspose.Words):

```markdown
# Sample Report

Here is an introductory paragraph.

![Sample image](md-resources/image001.png)

More text follows...
```

[Пример изображения](md-resources/image001.png)

> **Полезный совет:** Откройте сгенерированный файл `.md` в VS Code или любом просмотрщике Markdown; изображения должны отображаться мгновенно, поскольку относительные пути соответствуют структуре папок.

## Полный, готовый к запуску пример (без дополнительных блоков кода)

Ниже приведена автономная консольная программа, которую можно вставить в новый проект .NET и запустить. Она создаёт простой документ Word, добавляет изображение и затем **создаёт markdown из документа**, сохраняя изображение в подпапке.

```csharp
using System;
using System.IO;
using Aspose.Words;
using Aspose.Words.Saving;

class Program
{
    static void Main()
    {
        // 1️⃣ Create a sample Word document with an image
        var doc = new Document();
        var builder = new DocumentBuilder(doc);
        builder.Writeln("Hello, this is a test document.");
        builder.InsertImage("sample-image.png"); // Ensure this file exists next to exe

        // 2️⃣ Configure markdown export options (see Step 1 & 2 above)
        var markdownOptions = new MarkdownSaveOptions();
        markdownOptions.ResourceSavingCallback = new IResourceSavingCallback(
            (args) =>
            {
                const string folder = "md-resources/";
                Directory.CreateDirectory(folder);
                args.OutputFileName = Path.Combine(folder, args.ResourceFileName);
            });

        // 3️⃣ Save as markdown (Step 3)
        string outputFolder = Path.Combine(Environment.CurrentDirectory, "output");
        Directory.CreateDirectory(outputFolder);
        string markdownPath = Path.Combine(outputFolder, "ExportedDoc.md");
        doc.Save(markdownPath, markdownOptions);

        Console.WriteLine($"✅ Markdown saved to: {markdownPath}");
        Console.WriteLine("📂 Images saved in: md-resources/");
    }
}
```

**Что вы должны увидеть** после запуска:

```
✅ Markdown saved to: C:\MyProject\output\ExportedDoc.md
📂 Images saved in: md-resources/
```

Откройте `ExportedDoc.md` — ссылка на изображение будет указывать на `md-resources/sample-image.png`, и картинка отобразится корректно в любом просмотрщике Markdown.

## Распространённые проблемы и решения

- **Изображения не отображаются в предпросмотре markdown** — проверьте, что относительный путь в markdown (`md-resources/image001.png`) соответствует реальному расположению папки относительно файла `.md`.  
- **Дублирующиеся имена изображений вызывают перезапись** — добавьте уникальный идентификатор (GUID или инкрементный счётчик) внутри обратного вызова, чтобы гарантировать уникальные имена файлов.  
- **Большие документы вызывают нагрузку на память** — используйте `Document.OptimizeResources()` перед сохранением; это уменьшает потребление памяти, освобождая неиспользуемые потоки.  
- **Неподдерживаемые форматы изображений** — Aspose.Words поддерживает PNG, JPEG, BMP, GIF и TIFF. Конвертируйте неподдерживаемые форматы в один из этих перед добавлением их в исходный документ.

**В: Требуется ли коммерческая лицензия для использования в продакшене?**  
О: Да. Бесплатная оценочная лицензия доступна для тестирования, но для продакшн‑развёртываний необходима приобретённая лицензия Aspose.Words.

**В: Как библиотека обрабатывает документы, защищённые паролем?**  
О: Загрузите документ с помощью `new Document("file.docx", new LoadOptions { Password = "yourPassword" })` перед вызовом процедуры сохранения в markdown.
