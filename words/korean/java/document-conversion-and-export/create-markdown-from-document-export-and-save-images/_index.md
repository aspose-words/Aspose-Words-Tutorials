# docx를 마크다운으로 변환하고 이미지가 하위 폴더에 저장되도록 하는 방법

docx를 마크다운으로 변환하면서 모든 삽입된 그림을 깔끔하게 정리하고 싶다면, 바로 여기가 정답입니다. 많은 개발자들이 보고서, 매뉴얼, 블로그 초안을 프로그래밍으로 생성하고 결과 디렉터리에 이미지 파일이 뒤섞인 혼란스러운 상황에 직면합니다. 이 튜토리얼에서는 Aspose.Words for .NET을 사용한 깔끔한 콜백 기반 접근 방식을 보여줍니다. 문서를 마크다운으로 내보내고 각 이미지를 전용 *md‑resources* 폴더에 저장하며, 최종 마크다운 파일을 게시 준비 상태로 저장합니다.

> **빠른 개요:**  
> • `MarkdownSaveOptions` 설정  
> • 이미지를 리디렉션하기 위한 `IResourceSavingCallback` 구현  
> • 구성된 옵션으로 `Document.Save` 호출  

이제 콜백이 후처리보다 왜 선호되는지 이해했으니, 단계별 솔루션을 살펴보겠습니다.

## 빠른 답변
- **“convert docx to markdown”가 실제로 하는 일은 무엇인가요?** Word 처리 마크업을 일반 텍스트 마크다운으로 변환하면서 제목, 목록, 표 및 이미지 참조를 보존합니다.  
- **어떤 라이브러리가 변환을 담당하나요?** Aspose.Words for .NET은 Microsoft Word 없이도 작동하는 완전 관리형 서버‑사이드 API를 제공합니다.  
- **이미지 처리 코드를 작성해야 하나요?** 필요 없습니다; `IResourceSavingCallback`이 지정한 폴더에 각 이미지를 저장합니다.  
- **출력 폴더 이름을 변경할 수 있나요?** 물론입니다 – `"md-resources/"`를 원하는 상대 경로나 절대 경로로 교체하면 됩니다.  
- **이 솔루션이 .NET 6 및 이후 버전과 호환되나요?** 예, .NET 6+, .NET 5, .NET Core 3.1 및 .NET Framework 4.7+에서 실행됩니다.

## convert docx to markdown란 무엇인가요?
**Convert docx to markdown**는 Microsoft Word 문서(DOCX)를 받아 마크다운 구문(`.md`)을 사용해 동일한 내용을 나타내는 마크다운 파일을 생성하는 과정입니다. 변환은 구조적 요소를 보존하고 선택적으로 이미지와 같은 삽입된 리소스를 추출합니다.

변환은 Aspose.Words에 의해 수행되며, **35개 이상의 입력 및 출력 형식**(DOCX, PDF, HTML, Markdown 등)을 지원해 전체 파일을 메모리에 로드하지 않고도 수백 페이지 문서를 처리할 수 있습니다.

## 마크다운 내보내기에 Aspose.Words를 사용하는 이유
Aspose.Words는 문서를 메모리에서 처리하고 결과를 직접 대상 형식으로 기록하므로:

Aspose.Words는 높은 성능과 정확한 변환을 제공하면서 리소스 처리에 대한 완전한 제어를 가능하게 합니다. 후처리 단계가 필요 없으며 메모리 사용량을 줄이고 이미지, 표, 스타일이 마크다운 출력에 충실히 재현되도록 보장합니다.

- **속도:** 일반적인 200페이지 DOCX 파일은 표준 VM에서 2초 미만에 마크다운으로 변환됩니다.  
- **정확성:** 50개 이상의 내장 마크다운 변형을 모두 지원해 표, 코드 블록, 각주가 올바르게 렌더링됩니다.  
- **리소스 제어:** 내장 `IResourceSavingCallback`을 사용하면 각 이미지가 저장되는 위치를 정확히 지정할 수 있어 별도의 정리 단계가 필요 없습니다.

## docx를 마크다운으로 변환하는 방법은?
`new Document("source.docx")`로 소스 문서를 로드하고, `MarkdownSaveOptions`를 구성해 각 이미지를 `md-resources/`에 기록하는 콜백을 사용한 뒤 `doc.Save("output.md", saveOptions)`를 호출합니다. 이 세 단계 패턴은 파일을 변환하고 이미지를 추출하며, 상대 이미지 링크가 포함된 깔끔한 마크다운 파일을 한 번의 메서드 호출로 생성합니다.

### 단계 1: 마크다운 변환을 위한 저장 옵션 구성
MarkdownSaveOptions는 Aspose.Words가 문서를 마크다운으로 변환하는 방식을 구성합니다.

```csharp
// Step 1: Initialize Markdown save options
var markdownSaveOptions = new Aspose.Words.Saving.MarkdownSaveOptions();
```

```csharp
// Step 1: Initialize Markdown save options
var markdownSaveOptions = new Aspose.Words.Saving.MarkdownSaveOptions();
```

> **왜 중요한가:**  
> `MarkdownSaveOptions`를 명시적으로 생성하지 않으면, 라이브러리는 기본 설정으로 돌아가 이미지들을 Base64 문자열로 마크다운 파일에 직접 삽입합니다. 이 경우 파일이 크게 늘어나며 깔끔한 *images* 폴더를 갖는 목적이 무색해집니다.

### 단계 2: 이미지를 내보내기 위한 리소스 저장 콜백 정의
`IResourceSavingCallback`를 사용하면 내보내기 중 각 리소스(이미지, SVG)의 저장 위치를 제어할 수 있습니다.

이제 saver에게 각 이미지를 **어디에** 저장할지 알려줍니다. `IResourceSavingCallback` 인터페이스는 내보내기 중 발견되는 모든 리소스(이미지, SVG 등)에 대해 호출되는 훅을 제공합니다. 콜백 내부에서 우리는:

1. 대상 폴더가 존재하는지 확인합니다(`md-resources/`).  
2. `OutputFileName`을 폴더와 원본 리소스 이름을 결합한 값으로 설정합니다.  

```csharp
// Step 2: Hook into the resource‑saving pipeline
markdownSaveOptions.ResourceSavingCallback = new Aspose.Words.Saving.IResourceSavingCallback(
    (args) =>
    {
        // All images will be placed in "md-resources" relative to the output .md file
        const string folder = "md-resources/";
        Directory.CreateDirectory(folder);          // Create folder if it doesn’t exist

        // Preserve the original file name (e.g., image001.png) but prepend the folder path
        args.OutputFileName = Path.Combine(folder, args.ResourceFileName);

        // Optional: you could also change the format here (e.g., convert BMP to PNG)
        // args.ResourceFileName = Path.ChangeExtension(args.ResourceFileName, ".png");
    });
```

> **자주 묻는 질문:** *이미지를 저장하지 않고 삽입하고 싶다면?*  
> 콜백을 생략하거나 `args.OutputFileName = null;`로 설정하면 saver가 자동으로 이미지를 Base64 문자열로 삽입합니다.

> **예외 상황:** 일부 오래된 문서에는 중복 이미지 이름이 있습니다. 위 콜백은 이전 파일을 덮어씁니다. 이를 방지하려면 GUID를 추가할 수 있습니다:

```csharp
args.OutputFileName = Path.Combine(folder,
    $"{Path.GetFileNameWithoutExtension(args.ResourceFileName)}_{Guid.NewGuid()}{Path.GetExtension(args.ResourceFileName)}");
```

### 단계 3: 문서를 마크다운으로 저장하고 출력 확인
옵션을 완전히 구성한 후, 최종 호출은 마크다운 파일과 관련 이미지들을 디스크에 기록하는 한 줄 코드입니다.

```csharp
// Step 3: Perform the actual export
string outputPath = @"C:\Exports\MyReport.md";
doc.Save(outputPath, markdownSaveOptions);
```

모든 것이 정상적으로 진행되면 다음을 확인할 수 있습니다:

- `MyReport.md` – 소스 문서의 마크다운 표현.  
- `md-resources/` – `.md` 파일 옆에 위치한 폴더로, 추출된 모든 이미지(`image001.png`, `image002.jpg` 등)를 포함합니다.

**샘플 마크다운 스니펫** (Aspose.Words가 자동 생성):

```markdown
# Sample Report

Here is an introductory paragraph.

![Sample image](md-resources/image001.png)

More text follows...
```

[샘플 이미지](md-resources/image001.png)

> **프로 팁:** 생성된 `.md` 파일을 VS Code 또는 任意 마크다운 미리보기 프로그램에서 열면, 상대 경로가 폴더 구조와 일치하므로 이미지가 즉시 표시됩니다.

## 전체 실행 가능한 예제 (추가 코드 블록 없음)
아래는 새 .NET 프로젝트에 붙여넣고 실행할 수 있는 독립형 콘솔 프로그램입니다. 간단한 워드 문서를 만들고 이미지를 추가한 뒤, **문서에서 마크다운 생성**하면서 이미지를 하위 폴더에 저장합니다.

```csharp
using System;
using System.IO;
using Aspose.Words;
using Aspose.Words.Saving;

class Program
{
    static void Main()
    {
        // 1️⃣ Create a sample Word document with an image
        var doc = new Document();
        var builder = new DocumentBuilder(doc);
        builder.Writeln("Hello, this is a test document.");
        builder.InsertImage("sample-image.png"); // Ensure this file exists next to exe

        // 2️⃣ Configure markdown export options (see Step 1 & 2 above)
        var markdownOptions = new MarkdownSaveOptions();
        markdownOptions.ResourceSavingCallback = new IResourceSavingCallback(
            (args) =>
            {
                const string folder = "md-resources/";
                Directory.CreateDirectory(folder);
                args.OutputFileName = Path.Combine(folder, args.ResourceFileName);
            });

        // 3️⃣ Save as markdown (Step 3)
        string outputFolder = Path.Combine(Environment.CurrentDirectory, "output");
        Directory.CreateDirectory(outputFolder);
        string markdownPath = Path.Combine(outputFolder, "ExportedDoc.md");
        doc.Save(markdownPath, markdownOptions);

        Console.WriteLine($"✅ Markdown saved to: {markdownPath}");
        Console.WriteLine("📂 Images saved in: md-resources/");
    }
}
```

**실행 후 확인할 내용**:

```
✅ Markdown saved to: C:\MyProject\output\ExportedDoc.md
📂 Images saved in: md-resources/
```

`ExportedDoc.md`를 열면 이미지 참조가 `md-resources/sample-image.png`를 가리키며, 모든 마크다운 뷰어에서 이미지가 올바르게 표시됩니다.

## 일반적인 문제와 해결책
- **이미지가 마크다운 미리보기에서 보이지 않음** – 마크다운에 있는 상대 경로(`md-resources/image001.png`)가 `.md` 파일 기준 실제 폴더 위치와 일치하는지 확인하세요.  
- **중복 이미지 이름으로 인한 덮어쓰기** – 콜백 내부에서 고유 식별자(GUID 또는 증가 카운터)를 추가해 파일명을 구분하도록 합니다.  
- **대용량 문서로 인한 메모리 압박** – 저장 전에 `Document.OptimizeResources()`를 사용하면 사용되지 않는 스트림을 해제해 메모리 사용량을 줄입니다.  
- **지원되지 않는 이미지 형식** – Aspose.Words는 PNG, JPEG, BMP, GIF, TIFF를 지원합니다. 지원되지 않는 형식은 소스 문서에 추가하기 전에 이 중 하나로 변환하세요.

**Q: 프로덕션 사용에 상업 라이선스가 필요합니까?**  
A: 예. 테스트용 무료 평가 라이선스가 제공되지만, 프로덕션 배포에는 구매한 Aspose.Words 라이선스가 필요합니다.

**Q: 라이브러리는 비밀번호로 보호된 문서를 어떻게 처리하나요?**

**Q: 공식적으로 지원되는 .NET 버전은 무엇인가요?**  
A: Aspose.Words는 .NET Framework 4.7+, .NET Core 3.1+, .NET 5, .NET 6 이상을 지원합니다.

우리는 **docx를 마크다운으로 변환하는 방법**, **문서를 마크다운으로 내보내는 방법**, 그리고 **이미지를 하위 폴더에 저장하는 방법**을 깔끔한 콜백 기반 패턴으로 시연했습니다. 주요 요점은 다음과 같습니다:

- 세밀한 제어를 위해 `MarkdownSaveOptions`를 사용합니다.  
- `IResourceSavingCallback`을 구현해 이미지를 전용 폴더에 저장함으로써 마크다운을 깔끔하게 유지합니다.  
- `args.ResourceType`을 확인하면 동일한 기법을 SVG, 오디오 등 다른 리소스 유형에도 적용할 수 있습니다.

다음 단계로는 제목 스타일을 맞춤화하거나, CI 파이프라인에 통합하거나, 마크다운과 리소스를 포함한 ZIP을 반환하는 마이크로서비스로 노출하는 것이 있습니다. 이제 기본 요소가 준비되었으니 문서를 마크다운 파이프라인으로 자동화할 수 있습니다.
