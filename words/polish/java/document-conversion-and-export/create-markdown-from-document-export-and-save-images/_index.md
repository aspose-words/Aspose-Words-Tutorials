# Jak przekonwertować docx na markdown z obrazami w podfolderze

Jeśli potrzebujesz **convert docx to markdown** i chcesz, aby wszystkie osadzone obrazy były starannie uporządkowane, trafiłeś we właściwe miejsce. Wielu programistów generuje raporty, podręczniki lub szkice blogów programowo i kończy z chaotycznym zestawem plików obrazów rozrzuconych po katalogu wyjściowym. Ten tutorial pokazuje czyste, oparte na callbacku podejście przy użyciu Aspose.Words dla .NET, które eksportuje dokument do markdown, zapisuje każdy obraz w dedykowanym folderze *md‑resources* i zapisuje gotowy plik markdown gotowy do publikacji.

> **Szybki przegląd:**  
> • Set up `MarkdownSaveOptions`  
> • Implement an `IResourceSavingCallback` to redirect images  
> • Call `Document.Save` with the configured options  

Teraz, gdy rozumiesz, dlaczego callback jest lepszy niż post‑processing, przejdźmy do rozwiązania krok po kroku.

## Szybkie odpowiedzi
- **Co właściwie robi „convert docx to markdown”?** Przekształca znacznik Word‑processing na zwykły tekst markdown, zachowując nagłówki, listy, tabele i odwołania do obrazów.  
- **Która biblioteka obsługuje konwersję?** Aspose.Words dla .NET zapewnia w pełni zarządzane API po stronie serwera, które działa bez zainstalowanego Microsoft Word.  
- **Czy muszę pisać kod przetwarzający obrazy?** Nie; `IResourceSavingCallback` zajmuje się zapisywaniem każdego obrazu do wskazanego folderu.  
- **Czy mogę zmienić nazwę folderu wyjściowego?** Oczywiście – zamień `"md-resources/"` na dowolną względną lub bezwzględną ścieżkę, którą preferujesz.  
- **Czy rozwiązanie jest kompatybilne z .NET 6 i nowszymi?** Tak, działa na .NET 6+, .NET 5, .NET Core 3.1 oraz .NET Framework 4.7+.

Konwersję wykonuje Aspose.Words, biblioteka obsługująca **35+ formatów wejściowych i wyjściowych** — w tym DOCX, PDF, HTML i Markdown — umożliwiając obsługę dokumentów wielostronicowych bez ładowania całego pliku do pamięci.

## Jak przekonwertować docx na markdown? 

Załaduj dokument źródłowy przy pomocy `new Document("source.docx")`, skonfiguruj `MarkdownSaveOptions` tak, aby używał callbacku zapisującego każdy obraz do `md-resources/`, a następnie wywołaj `doc.Save("output.md", saveOptions)`. Ten trzyetapowy wzorzec konwertuje plik, wyodrębnia obrazy i tworzy czysty plik markdown z względnymi odnośnikami do obrazów — wszystko w jednej metodzie.

### Krok 1: skonfiguruj opcje zapisu dla konwersji markdown

MarkdownSaveOptions konfiguruje, jak Aspose.Words konwertuje dokument do Markdown.

```csharp
// Step 1: Initialize Markdown save options
var markdownSaveOptions = new Aspose.Words.Saving.MarkdownSaveOptions();
```

```csharp
// Step 1: Initialize Markdown save options
var markdownSaveOptions = new Aspose.Words.Saving.MarkdownSaveOptions();
```

> **Why this matters:**  
> Without explicitly creating `MarkdownSaveOptions`, the library falls back to default settings that embed images directly into the Markdown file as Base64 strings. That makes the file huge and defeats the purpose of having a clean *images* folder.

> **Dlaczego to ważne:**  
> Bez jawnego utworzenia `MarkdownSaveOptions` biblioteka używa domyślnych ustawień, które osadzają obrazy bezpośrednio w pliku Markdown jako ciągi Base64. Powoduje to ogromny plik i niweczy cel posiadania czystego folderu *images*.

### Krok 2: zdefiniuj callback zapisywania zasobów, aby eksportować obrazy

`IResourceSavingCallback` pozwala kontrolować, gdzie każdy zasób (obraz, SVG) jest zapisywany podczas eksportu.

Teraz mówimy saverowi **gdzie** umieścić każdy obraz. Interfejs `IResourceSavingCallback` daje hak, który wywoływany jest dla każdego zasobu (obraz, SVG, itp.) wykrytego podczas eksportu. Wewnątrz callbacku:

1. Upewnij się, że docelowy folder istnieje (`md-resources/`).  
2. Ustaw `OutputFileName` na folder plus oryginalna nazwa zasobu.  

```csharp
// Step 2: Hook into the resource‑saving pipeline
markdownSaveOptions.ResourceSavingCallback = new Aspose.Words.Saving.IResourceSavingCallback(
    (args) =>
    {
        // All images will be placed in "md-resources" relative to the output .md file
        const string folder = "md-resources/";
        Directory.CreateDirectory(folder);          // Create folder if it doesn’t exist

        // Preserve the original file name (e.g., image001.png) but prepend the folder path
        args.OutputFileName = Path.Combine(folder, args.ResourceFileName);

        // Optional: you could also change the format here (e.g., convert BMP to PNG)
        // args.ResourceFileName = Path.ChangeExtension(args.ResourceFileName, ".png");
    });
```

> **Common question:** *What if I want to embed images instead of saving them?*  
> Just skip the callback or set `args.OutputFileName = null;` – the saver will embed the image as a Base64 string automatically.

> **Powszechne pytanie:** *Co jeśli chcę osadzić obrazy zamiast je zapisywać?*  
> Po prostu pomiń callback lub ustaw `args.OutputFileName = null;` – saver automatycznie osadzi obraz jako ciąg Base64.

> **Edge case:** Some older documents contain duplicate image names. The callback above will overwrite the previous file. To avoid that, you could append a GUID:

> **Przypadek brzegowy:** Niektóre starsze dokumenty zawierają duplikaty nazw obrazów. Powyższy callback nadpisze poprzedni plik. Aby tego uniknąć, możesz dodać GUID:

```csharp
args.OutputFileName = Path.Combine(folder,
    $"{Path.GetFileNameWithoutExtension(args.ResourceFileName)}_{Guid.NewGuid()}{Path.GetExtension(args.ResourceFileName)}");
```

### Krok 3: zapisz dokument jako markdown i zweryfikuj wynik

Po pełnej konfiguracji opcji, finalne wywołanie to jednowierszowy kod, który zapisuje plik Markdown oraz powiązane obrazy na dysk.

```csharp
// Step 3: Perform the actual export
string outputPath = @"C:\Exports\MyReport.md";
doc.Save(outputPath, markdownSaveOptions);
```

Jeśli wszystko pójdzie dobrze, zobaczysz:

- `MyReport.md` – reprezentacja Markdown twojego dokumentu źródłowego.  
- `md-resources/` – folder obok pliku `.md` zawierający każdy wyodrębniony obraz (np. `image001.png`, `image002.jpg`).  

**Sample markdown snippet** (auto‑generated by Aspose.Words):

```markdown
# Sample Report

Here is an introductory paragraph.

![Sample image](md-resources/image001.png)

More text follows...
```

[Sample image](md-resources/image001.png)

> **Pro tip:** Open the generated `.md` file in VS Code or any Markdown previewer; the images should render instantly because the relative paths match the folder structure.

> **Wskazówka:** Otwórz wygenerowany plik `.md` w VS Code lub dowolnym podglądzie Markdown; obrazy powinny wyświetlać się natychmiast, ponieważ względne ścieżki pasują do struktury folderu.

## Pełny, uruchamialny przykład (bez dodatkowych bloków kodu)

Poniżej znajduje się samodzielny program konsolowy, który możesz wkleić do nowego projektu .NET i uruchomić. Tworzy prosty dokument Word, dodaje obraz, a następnie **tworzy markdown z dokumentu** zapisując obraz w podfolderze.

```csharp
using System;
using System.IO;
using Aspose.Words;
using Aspose.Words.Saving;

class Program
{
    static void Main()
    {
        // 1️⃣ Create a sample Word document with an image
        var doc = new Document();
        var builder = new DocumentBuilder(doc);
        builder.Writeln("Hello, this is a test document.");
        builder.InsertImage("sample-image.png"); // Ensure this file exists next to exe

        // 2️⃣ Configure markdown export options (see Step 1 & 2 above)
        var markdownOptions = new MarkdownSaveOptions();
        markdownOptions.ResourceSavingCallback = new IResourceSavingCallback(
            (args) =>
            {
                const string folder = "md-resources/";
                Directory.CreateDirectory(folder);
                args.OutputFileName = Path.Combine(folder, args.ResourceFileName);
            });

        // 3️⃣ Save as markdown (Step 3)
        string outputFolder = Path.Combine(Environment.CurrentDirectory, "output");
        Directory.CreateDirectory(outputFolder);
        string markdownPath = Path.Combine(outputFolder, "ExportedDoc.md");
        doc.Save(markdownPath, markdownOptions);

        Console.WriteLine($"✅ Markdown saved to: {markdownPath}");
        Console.WriteLine("📂 Images saved in: md-resources/");
    }
}
```

**What you should see** after running:

**Co powinieneś zobaczyć** po uruchomieniu:

```
✅ Markdown saved to: C:\MyProject\output\ExportedDoc.md
📂 Images saved in: md-resources/
```

Otwórz `ExportedDoc.md` – odwołanie do obrazu wskaże na `md-resources/sample-image.png`, a obraz wyświetli się poprawnie w każdym podglądzie Markdown.

## Często zadawane warianty

| Scenariusz | Jak dostosować kod |
|------------|--------------------|
| **Skip image export** (embed as Base64) | Omit `ResourceSavingCallback` entirely, or set `args.OutputFileName = null;` inside the callback. |
| **Change image format** (e.g., all PNG) | Inside the callback, modify `args.ResourceFileName` and optionally convert the stream before writing. |
| **Custom folder name** | Replace `"md-resources/"` with any relative or absolute path you prefer. |
| **Multiple documents in a batch** | Loop over a collection of `Document` objects, reusing the same `MarkdownSaveOptions` instance (just ensure the folder is cleared or uniquely named per run). |

## Typowe problemy i rozwiązania

- **Images not appearing in the markdown preview** – Verify that the relative path in the markdown (`md-resources/image001.png`) matches the actual folder location relative to the `.md` file.  
  **Obrazy nie wyświetlają się w podglądzie markdown** – Sprawdź, czy względna ścieżka w markdown (`md-resources/image001.png`) odpowiada rzeczywistej lokalizacji folderu względem pliku `.md`.  

- **Duplicate image names causing overwrites** – Append a unique identifier (GUID or incremental counter) inside the callback to guarantee distinct filenames.  
  **Duplikaty nazw obrazów powodujące nadpisywanie** – Dodaj unikalny identyfikator (GUID lub licznik) w callbacku, aby zapewnić różne nazwy plików.  

- **Large documents causing memory pressure** – Use `Document.OptimizeResources()` before saving; this reduces memory consumption by disposing of unused streams.  
  **Duże dokumenty powodujące obciążenie pamięci** – Użyj `Document.OptimizeResources()` przed zapisem; zmniejsza to zużycie pamięci poprzez zwalnianie nieużywanych strumieni.  

- **Unsupported image formats** – Aspose.Words supports PNG, JPEG, BMP, GIF, and TIFF. Convert unsupported formats to one of these before adding them to the source document.  
  **Nieobsługiwane formaty obrazów** – Aspose.Words obsługuje PNG, JPEG, BMP, GIF i TIFF. Przekonwertuj nieobsługiwane formaty na jeden z tych przed dodaniem ich do dokumentu źródłowego.
