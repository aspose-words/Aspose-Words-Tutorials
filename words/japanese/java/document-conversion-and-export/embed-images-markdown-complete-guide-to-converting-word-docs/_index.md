# 画像を埋め込むMarkdown – Word文書変換の完全ガイド

WordファイルをクリーンなMarkdownドキュメントに変換する際に、**embed images markdown** が必要になることを考えたことはありますか？ あなたは一人ではありません。多くの開発者は、画像が消えてしまったり、単純な convert‑docx‑to‑markdown 操作の後に壊れたリンクになったりして壁にぶつかります。良いニュースは、C# と Aspose.Words の数行で、すべての画像をMarkdownファイルにBase64文字列として直接埋め込めることです—外部アセットは不要です。このガイドでは、**how to embed images** を学び、Markdownを自己完結型かつポータブルに保つ方法を紹介します。

## クイック回答
- **外部ファイルなしで画像を埋め込めますか？** Yes, use Base64 data URIs generated by Aspose.Words.  
- **どの .NET バージョンがサポートされていますか？** .NET 6+, .NET 5, .NET Core 3.1, and .NET Framework 4.6+.  
- **本番環境でライセンスが必要ですか？** A commercial license is required; a free trial works for evaluation.  
- **大きな画像はファイルサイズを膨らませますか？** Base64 adds ~33 % size overhead; consider compressing images first.  
- **バッチ変換は可能ですか？** Absolutely – wrap the same logic in a loop to process multiple files.

## Markdownに画像を埋め込む方法

Word文書をロードし、`MarkdownSaveOptions` に `ResourceSavingCallback` を設定して結果を保存します。コールバックはすべての画像ファイル参照を `data:image/...;base64,` URI に置き換え、生成された `.md` ファイルにすべてのビジュアル資産がインラインで含まれることを保証します。このアプローチは画像の数に関係なく機能し、必要なのは Aspose.Words ライブラリだけです—追加の画像処理ツールは不要です。

## なぜ画像をMarkdownに埋め込むのか

画像を直接Markdown (`![alt text](data:image/png;base64,…)`) に埋め込むことで、生成されたファイルが自己完結型になることが保証されます。特に次のような場合に便利です。

1. 外部資産を除去するプラットフォームでMarkdownを共有する場合。  
2. 記事ごとに単一ファイルを保持したいGitリポジトリにドキュメントを保存する場合。  
3. 画像フォルダーなしでMarkdownを読み取る静的サイトを生成する場合。

埋め込みを省略すると、対象環境に存在しないパスを指す画像リンクが残り、壊れたドキュメントの典型的な原因となります。

## Aspose.Words とは？

Aspose.Words は、Microsoft Word をインストールせずに Word 文書の作成、編集、変換、レンダリングを可能にする .NET ライブラリです。**35+** の入力・出力フォーマットをサポートし、DOCX、PDF、HTML、Markdown などに対応します。典型的なサーバー上で 500 ページの文書を 3 秒未満で処理できます。

## 変換はどのように機能しますか？

Aspose.Words は Word ファイルをメモリ内のノードツリーに解析します。画像データは `Shape` ノードに格納されます。`ResourceSavingCallback` を提供することで、各画像ストリームを捕捉し、Base64 に変換して、セーバーにデータ URI を直接埋め込むよう指示します。残りの文書（テキスト、テーブル、見出し）は標準的な Markdown 構文として出力されます。

## 前提条件
- .NET 6+（または .NET Framework 4.6+）
- Aspose.Words for .NET NuGet パッケージ
- Visual Studio や VS Code などの C# IDE

## 手順 1: ソースドキュメントをロードする

`Document` クラスは Aspose.Words のトップレベルオブジェクトで、メモリ内の単一 Word ファイルを表します。インスタンス化後、すべての読み書き操作はこのオブジェクトを通じて行われます。

コードは次の一行でロードできます（プレースホルダーは元のコードブロックが入る場所です）：

```csharp
// Step 1: Load the source document
Document doc = new Document("YOUR_DIRECTORY/input.docx");
```

> **Why this matters** – Loading the document gives you access to its internal node tree, including all `Shape` nodes that hold images. Without this step, there’s nothing to embed.

## 手順 2: Markdown保存オプションを設定する

`MarkdownSaveOptions` インスタンスを作成します。このオブジェクトは変換時の動作を指示し、画像を埋め込むかどうかを含めて設定できます。

```csharp
// Step 2: Create Markdown save options
MarkdownSaveOptions markdownSaveOptions = new MarkdownSaveOptions();
```

ここでプロパティ（例: `ExportImagesAsBase64 = true`）を調整できますが、より細かい制御と画像ごとのログ取得のためにコールバックを使用します。

## 手順 3: 画像をBase64として埋め込む

`ResourceSavingCallback` は変換中に外部リソースの保存方法を制御できるデリゲートです。  
`ResourceSavingResult.Embed` はセーバーにファイル参照ではなくデータ URI を埋め込むよう指示します。

以下が解決策の核心です。`ResourceSavingCallback` を割り当てることで、Aspose.Words が書き出そうとするすべての画像を捕捉し、インメモリの Base64 ストリームに置き換えます。

```csharp
// Step 3: Configure the callback to embed all images as Base64
markdownSaveOptions.ResourceSavingCallback = resourceInfo =>
{
    // The stream contains the original image bytes (PNG, JPEG, etc.)
    // We simply return a result that tells the saver to embed it.
    return ResourceSavingResult.Embed(resourceInfo.Stream);
};
```

**何が起きているか？**  
- `resourceInfo.Stream` は生の画像バイトを保持します。  
- `ResourceSavingResult.Embed` はセーバーにファイル参照ではなく `data:` URI を生成させます。  
- コールバックは*すべての*画像に対して実行されるため、シェイプを手動で列挙する必要はありません。

## 手順 4: ドキュメントをMarkdownとして保存する

最後に、Markdown ファイルをディスクに書き出します。前ステップのコールバックにより、すべての画像が Markdown 内の Base64 文字列として埋め込まれます。

```csharp
// Step 4: Save the document as a Markdown file
doc.Save("YOUR_DIRECTORY/output.md", markdownSaveOptions);
```

`output.md` を開くと次のような行が見えるはずです：

```markdown
![Image 0](data:image/png;base64,iVBORw0KGgoAAAANSUhEUgAA...)
```

この行は完全に埋め込まれた画像で、外部ファイルは不要です。

## 完全な動作例

以下は実行可能なコンソールアプリの全体例です。パスをコピー＆ペーストして調整してください。

```csharp
using Aspose.Words;
using Aspose.Words.Saving;

class Program
{
    static void Main()
    {
        // Load the DOCX
        Document doc = new Document("YOUR_DIRECTORY/input.docx");

        // Prepare Markdown options
        MarkdownSaveOptions options = new MarkdownSaveOptions();

        // Embed every image as Base64
        options.ResourceSavingCallback = resourceInfo =>
        {
            // Optional: Log the image name for debugging
            Console.WriteLine($"Embedding image: {resourceInfo.FileName}");
            return ResourceSavingResult.Embed(resourceInfo.Stream);
        };

        // Save as .md
        doc.Save("YOUR_DIRECTORY/output.md", options);

        Console.WriteLine("Conversion complete – images are now embedded!");
    }
}
```

プログラムを実行し、任意の Markdown ビューアで `output.md` を開くと、元の Word レイアウトが画像付きで保持されていることが確認できます。

## よくある落とし穴とエッジケース

| 問題 | 発生理由 | 対策 |
|------|----------|------|
| **大きな画像がMarkdownサイズを膨らませる** | Base64 は約33 % のオーバーヘッドを追加します。 | 埋め込む前に画像をリサイズまたは圧縮するか、外部資産用に `ExportImagesAsBase64 = false` を使用します。 |
| **未対応の画像形式（例: WMF）** | Aspose.Words はベクタ形式を自動的に PNG に変換しないことがあります。 | Word で WMF/EMF を PNG に変換するか、`ImageSaveOptions` でラスタライズします。 |
| **巨大文書でのメモリ圧迫** | コールバックが各画像をメモリに読み込むため。 | 文書をチャンクに分割して処理するか、プロセスのメモリ上限を増やします。 |
| **代替テキストが欠如** | デフォルトで Aspose.Words が汎用の代替テキストを生成することがあります。 | 変換前に Word 側で `Shape.AlternativeText` を設定するか、変換後に Markdown を後処理して意味のある説明を追加します。 |
| **ファイルパスが正しくない** | ハードコーディングされたパスは `FileNotFoundException` を引き起こします。 | `Path.Combine` と環境変数を使用して堅牢なパス処理を行います。 |

## バッチで **convert docx to markdown** を行う方法

各 Word ファイルをループでロードし、同じ `MarkdownSaveOptions` を再利用して `Save` を呼び出します。このパターンにより、手動介入なしで各ソースファイルの Markdown を保存できます。ファイルパスのコレクションを反復処理することで、各変換をログに記録し、個別にエラー処理を行い、埋め込み前に画像を圧縮して最終的な Markdown サイズを抑えることも可能です。

```csharp
string[] files = Directory.GetFiles("YOUR_DIRECTORY", "*.docx");
foreach (var file in files)
{
    Document doc = new Document(file);
    string outPath = Path.ChangeExtension(file, ".md");
    doc.Save(outPath, options);
}
```

## よくある質問

**Q: このアプローチをウェブアプリケーションで使用できますか？**  
A: はい、Aspose.Words は ASP.NET Core、Azure Functions、その他の .NET Web ホストで動作します。サーバーの一時フォルダーに大きなファイルを書き出さないように注意してください。

**Q: パスワード保護された Word ファイルに対応していますか？**  
A: もちろんです。変換前に `Document` コンストラクタまたは `LoadOptions` にパスワードを渡すだけです。

**Q: 処理できる最大ファイルサイズはどれくらいですか？**  
A: Aspose.Words は数百ページ規模の文書を扱えます。唯一の制限は利用可能なメモリです。コールバックを使用すれば画像はストリーム処理になるため、メモリ使用量は抑えられます。

**Q: テーブルは正しく変換されますか？**  
A: デフォルトではテーブルは Markdown テーブルに変換されます。より正確な制御が必要な場合は `options.ExportTableStructure = true` を有効にしてください。

**Q: 本番環境でライセンスは必須ですか？**  
A: はい、商用ライセンスを取得すれば評価制限が解除されます。開発・テスト用に無料トライアルが利用可能です。
