# docx を画像付きでサブフォルダーに変換する方法

もし **docx を markdown に変換** しながら、埋め込み画像をきれいに整理したいのであれば、ここが最適です。多くの開発者がレポートやマニュアル、ブログ草稿をプログラムで生成し、出力ディレクトリに画像ファイルが散在する混沌とした状態に陥ります。このチュートリアルでは、Aspose.Words for .NET を使用したクリーンなコールバック駆動アプローチを示し、ドキュメントを markdown にエクスポートし、各画像を専用の *md‑resources* フォルダーに保存し、公開準備が整った markdown ファイルを生成します。

> **概要:**  
> • `MarkdownSaveOptions` を設定  
> • 画像の保存先を変更する `IResourceSavingCallback` を実装  
> • 設定したオプションで `Document.Save` を呼び出す  

コールバックが事後処理よりも好ましい理由が理解できたので、ステップバイステップの解決策に進みましょう。

## 簡単な回答
- **「docx を markdown に変換」 とは実際に何をするのですか？** Word のマークアップをプレーンテキストの markdown に変換し、見出し、リスト、テーブル、画像参照を保持します。  
- **変換を担当するライブラリはどれですか？** Aspose.Words for .NET が、Microsoft Word がインストールされていなくても動作する完全管理型サーバーサイド API を提供します。  
- **画像処理のコードを書く必要がありますか？** いいえ。`IResourceSavingCallback` が画像の保存を自動的に処理します。  
- **出力フォルダー名を変更できますか？** もちろんです。`"md-resources/"` を任意の相対パスまたは絶対パスに置き換えてください。  
- **このソリューションは .NET 6 以降と互換性がありますか？** はい、.NET 6+、.NET 5、.NET Core 3.1、.NET Framework 4.7+ で動作します。

## docx を markdown に変換するとは？
**Convert docx to markdown** は、Microsoft Word 文書（DOCX）を取得し、同じ内容を markdown（`.md`）構文で表現したファイルを生成するプロセスです。変換は構造要素を保持し、必要に応じて埋め込みリソース（画像など）を抽出します。

変換は Aspose.Words によって実行されます。このライブラリは **35 以上の入力・出力フォーマット**（DOCX、PDF、HTML、Markdown など）をサポートし、数百ページに及ぶ文書でもメモリに全体を読み込まずに処理できます。

## なぜ Aspose.Words を markdown エクスポートに使うのか？
Aspose.Words はメモリ内で文書を処理し、結果を直接ターゲット形式に書き出すため、次のような利点があります。

Aspose.Words は高性能で正確な変換を提供し、リソース処理を完全に制御できます。事後処理ステップが不要になり、メモリ使用量が削減され、画像、テーブル、スタイルが markdown 出力に忠実に再現されます。

- **速度:** 標準的な VM 上で 200 ページ程度の DOCX を 2 秒未満で markdown に変換。  
- **正確性:** 50 以上の組み込み markdown 方言をサポートし、テーブル、コードブロック、脚注が正しくレンダリング。  
- **リソース制御:** 組み込みの `IResourceSavingCallback` により、各画像の保存先を正確に指定でき、別途クリーンアップする必要がなくなります。

## 前提条件

- .NET 6.0 以降（.NET Framework 4.7+ でも可）  
- Aspose.Words for .NET（NuGet パッケージ `Aspose.Words`）  
- ソースとなる `Document` オブジェクト（DOCX、PDF、RTF など）  

追加のライブラリは不要です。コールバック API は Aspose.Words に組み込まれています。

## docx を markdown に変換する方法

`new Document("source.docx")` でソース文書を読み込み、`MarkdownSaveOptions` を設定して画像を書き出すコールバックを指定し、`doc.Save("output.md", saveOptions)` を呼び出します。この 3 ステップでファイル変換、画像抽出、相対画像リンク付きのクリーンな markdown ファイル生成が一度のメソッド呼び出しで完了します。

### Step 1: markdown 変換用の保存オプションを構成

`MarkdownSaveOptions` は Aspose.Words が文書を Markdown に変換する方法を設定します。

```csharp
// Step 1: Initialize Markdown save options
var markdownSaveOptions = new Aspose.Words.Saving.MarkdownSaveOptions();
```

```csharp
// Step 1: Initialize Markdown save options
var markdownSaveOptions = new Aspose.Words.Saving.MarkdownSaveOptions();
```

> **重要ポイント:**  
> `MarkdownSaveOptions` を明示的に作成しないと、ライブラリはデフォルト設定で画像を Base64 文字列として Markdown に埋め込んでしまいます。これではファイルが巨大になり、クリーンな *images* フォルダーを持つ目的が失われます。

### Step 2: 画像をエクスポートするリソース保存コールバックを定義

`IResourceSavingCallback` を使用すると、エクスポート中に各リソース（画像、SVG）の保存先を制御できます。

ここでセーバーに **画像の保存先** を指示します。`IResourceSavingCallback` インターフェイスは、エクスポート時に検出されたすべてのリソース（画像、SVG など）に対してフックを提供します。コールバック内で以下を行います。

1. ターゲットフォルダーが存在することを確認（`md-resources/`）。  
2. `OutputFileName` をフォルダー名＋元のリソース名に設定。  

```csharp
// Step 2: Hook into the resource‑saving pipeline
markdownSaveOptions.ResourceSavingCallback = new Aspose.Words.Saving.IResourceSavingCallback(
    (args) =>
    {
        // All images will be placed in "md-resources" relative to the output .md file
        const string folder = "md-resources/";
        Directory.CreateDirectory(folder);          // Create folder if it doesn’t exist

        // Preserve the original file name (e.g., image001.png) but prepend the folder path
        args.OutputFileName = Path.Combine(folder, args.ResourceFileName);

        // Optional: you could also change the format here (e.g., convert BMP to PNG)
        // args.ResourceFileName = Path.ChangeExtension(args.ResourceFileName, ".png");
    });
```

> **よくある質問:** *画像を保存せずに埋め込みたい場合は？*  
> コールバックを省略するか、`args.OutputFileName = null;` と設定すれば、セーバーは自動的に画像を Base64 文字列として埋め込みます。

> **エッジケース:** 古い文書で画像名が重複している場合、上記のコールバックは前のファイルを上書きします。回避するには GUID を付加できます。

```csharp
args.OutputFileName = Path.Combine(folder,
    $"{Path.GetFileNameWithoutExtension(args.ResourceFileName)}_{Guid.NewGuid()}{Path.GetExtension(args.ResourceFileName)}");
```

### Step 3: 文書を markdown として保存し、出力を確認

オプションがすべて設定されたら、最終呼び出しは Markdown ファイルと関連画像をディスクに書き出すワンライナーです。

```csharp
// Step 3: Perform the actual export
string outputPath = @"C:\Exports\MyReport.md";
doc.Save(outputPath, markdownSaveOptions);
```

正常に完了すると次のようになります。

- `MyReport.md` – ソース文書の Markdown 表現。  
- `md-resources/` – `.md` ファイルの隣に作成されるフォルダーで、抽出されたすべての画像（例: `image001.png`, `image002.jpg`）が格納されます。  

**サンプル markdown スニペット**（Aspose.Words が自動生成）:

```markdown
# Sample Report

Here is an introductory paragraph.

![Sample image](md-resources/image001.png)

More text follows...
```

[サンプル画像](md-resources/image001.png)

> **プロのコツ:** 生成された `.md` ファイルを VS Code や任意の Markdown プレビューアで開くと、相対パスがフォルダー構造と一致しているため画像が即座に表示されます。

## 完全な実行可能サンプル（追加コードブロックなし）

以下は新規 .NET プロジェクトに貼り付けて実行できる、自己完結型コンソールプログラムです。シンプルな Word 文書を作成し、画像を追加し、**文書から markdown を作成** しつつ画像をサブフォルダーに保存します。

```csharp
using System;
using System.IO;
using Aspose.Words;
using Aspose.Words.Saving;

class Program
{
    static void Main()
    {
        // 1️⃣ Create a sample Word document with an image
        var doc = new Document();
        var builder = new DocumentBuilder(doc);
        builder.Writeln("Hello, this is a test document.");
        builder.InsertImage("sample-image.png"); // Ensure this file exists next to exe

        // 2️⃣ Configure markdown export options (see Step 1 & 2 above)
        var markdownOptions = new MarkdownSaveOptions();
        markdownOptions.ResourceSavingCallback = new IResourceSavingCallback(
            (args) =>
            {
                const string folder = "md-resources/";
                Directory.CreateDirectory(folder);
                args.OutputFileName = Path.Combine(folder, args.ResourceFileName);
            });

        // 3️⃣ Save as markdown (Step 3)
        string outputFolder = Path.Combine(Environment.CurrentDirectory, "output");
        Directory.CreateDirectory(outputFolder);
        string markdownPath = Path.Combine(outputFolder, "ExportedDoc.md");
        doc.Save(markdownPath, markdownOptions);

        Console.WriteLine($"✅ Markdown saved to: {markdownPath}");
        Console.WriteLine("📂 Images saved in: md-resources/");
    }
}
```

**実行後に期待される出力**:

```
✅ Markdown saved to: C:\MyProject\output\ExportedDoc.md
📂 Images saved in: md-resources/
```

`ExportedDoc.md` を開くと、画像参照が `md-resources/sample-image.png` を指しており、任意の Markdown ビューアで正しく表示されます。

## よくあるバリエーション

| シナリオ | コードの適用方法 |
|----------|-------------------|
| **画像のエクスポートをスキップ**（Base64 埋め込み） | `ResourceSavingCallback` を完全に省略するか、コールバック内で `args.OutputFileName = null;` を設定 |
| **画像形式を変更**（例: すべて PNG） | コールバック内で `args.ResourceFileName` を変更し、必要に応じてストリームを変換 |
| **カスタムフォルダー名** | `"md-resources/"` を任意の相対または絶対パスに置き換え |
| **バッチで複数文書を処理** | `Document` オブジェクトのコレクションをループし、同じ `MarkdownSaveOptions` インスタンスを再利用（フォルダーをクリアするか、実行ごとに一意の名前を付ける） |

## 共通の問題と解決策

- **画像が markdown プレビューに表示されない** – markdown 内の相対パス（`md-resources/image001.png`）が `.md` ファイルから見た実際のフォルダー位置と一致しているか確認してください。  
- **画像名が重複して上書きされる** – コールバック内で GUID やインクリメンタルカウンタを付加し、ファイル名を一意にしてください。  
- **大容量文書でメモリ圧迫** – 保存前に `Document.OptimizeResources()` を呼び出すと、未使用ストリームが破棄されメモリ使用量が削減されます。  
- **サポート外の画像形式** – Aspose.Words は PNG、JPEG、BMP、GIF、TIFF をサポートしています。サポート外形式は事前にこれらのいずれかに変換してください。

## よくある質問

**Q: このアプローチを ZIP ファイルを返す ASP .NET Web API で使えますか？**  
A: はい。マークダウンと画像を一時フォルダーに生成し、`ZipArchive` に追加してクライアントにストリーム返却すれば、同じ `MarkdownSaveOptions` とコールバックがそのまま利用できます。

**Q: 変換は見出しやテーブルなどの Word スタイルを保持しますか？**  
A: 完全に保持します。Aspose.Words は Word の見出しスタイルを markdown の `#` 見出しにマッピングし、テーブルは markdown のパイプ構文に変換してセル内容と配置を維持します。

**Q: 本番環境での使用には商用ライセンスが必要ですか？**  
A: はい。評価ライセンスはテスト用に利用可能ですが、本番展開には購入した Aspose.Words ライセンスが必要です。

**Q: パスワード保護された文書はどう扱いますか？**  
A: `new Document("file.docx", new LoadOptions { Password = "yourPassword" })` で文書をロードしてから markdown 保存処理を呼び出します。

**Q: 公式にサポートされている .NET バージョンは？**  
A: Aspose.Words は .NET Framework 4.7+、.NET Core 3.1+、.NET 5、.NET 6 以降を公式にサポートしています。

## 結論

**docx を markdown に変換し、画像をサブフォルダーに保存する** 方法を、クリーンなコールバック駆動パターンで実演しました。重要なポイントは次の通りです。

- `MarkdownSaveOptions` を使用して細かい制御を行う。  
- `IResourceSavingCallback` を実装して画像を専用フォルダーに振り分け、markdown をすっきり保つ。  
- 同様の手法で SVG や音声など他のリソースタイプも `args.ResourceType` をチェックして処理可能。

次のステップとしては、見出しスタイルのカスタマイズ、CI パイプラインへの組み込み、または markdown とリソースを含む ZIP を返すマイクロサービス化などが考えられます。これでドキュメントから markdown へのパイプラインを自信を持って自動化できるようになりました。
