# Hur man konverterar docx till markdown med bilder i en undermapp

Om du behöver **konvertera docx till markdown** samtidigt som du håller varje inbäddad bild snyggt organiserad, har du kommit till rätt ställe. Många utvecklare genererar rapporter, manualer eller bloggutkast programatiskt och slutar med en kaotisk blandning av bildfiler utspridda i utmatningskatalogen. Den här handledningen visar dig ett rent, callback‑drivet tillvägagångssätt med Aspose.Words för .NET som exporterar ett dokument till markdown, lagrar varje bild i en dedikerad *md‑resources*‑mapp och sparar den slutliga markdown‑filen klar för publicering.

> **Snabb översikt:**  
> • Ställ in `MarkdownSaveOptions`  
> • Implementera en `IResourceSavingCallback` för att omdirigera bilder  
> • Anropa `Document.Save` med de konfigurerade alternativen  

Nu när du förstår varför en callback är att föredra framför efterbearbetning, låt oss dyka ner i steg‑för‑steg‑lösningen.

## Snabba svar
- **Vad gör “convert docx to markdown” egentligen?** Den omvandlar Word‑processens markup till ren text‑markdown samtidigt som den bevarar rubriker, listor, tabeller och bildreferenser.  
- **Vilket bibliotek hanterar konverteringen?** Aspose.Words för .NET tillhandahåller ett fullständigt hanterat server‑side‑API som fungerar utan att Microsoft Word är installerat.  
- **Behöver jag skriva någon bildbehandlingskod?** Nej; `IResourceSavingCallback` sköter att spara varje bild till den mapp du anger.  
- **Kan jag ändra namn på utmatningsmappen?** Absolut – ersätt `"md-resources/"` med någon relativ eller absolut sökväg du föredrar.  
- **Är lösningen kompatibel med .NET 6 och senare?** Ja, den körs på .NET 6+, .NET 5, .NET Core 3.1 och .NET Framework 4.7+.

## Vad är konvertering av docx till markdown?
**Convert docx to markdown** är processen att ta ett Microsoft Word‑dokument (DOCX) och generera en markdown‑fil (`.md`) som representerar samma innehåll med markdown‑syntax. Konverteringen bevarar strukturella element och kan valfritt extrahera inbäddade resurser såsom bilder.

Konverteringen utförs av Aspose.Words, ett bibliotek som stödjer **35+ in‑ och utdataformat**—inklusive DOCX, PDF, HTML och Markdown—vilket gör att du kan hantera dokument på flera hundra sidor utan att läsa in hela filen i minnet.

## Varför använda Aspose.Words för markdown‑export?
Aspose.Words bearbetar dokument i minnet och skriver resultatet direkt till målformatet, vilket innebär:

Aspose.Words erbjuder högpresterande, exakt konvertering samtidigt som du får full kontroll över resurshanteringen. Det eliminerar behovet av efterbearbetningssteg, minskar minnesanvändningen och säkerställer att bilder, tabeller och stilar återges troget i markdown‑utdata.

- **Hastighet:** Vanliga 200‑sidiga DOCX‑filer konverteras till markdown på under 2 sekunder på en standard‑VM.  
- **Noggrannhet:** Alla 50+ inbyggda markdown‑varianter stöds, vilket säkerställer att tabeller, kodblock och fotnoter renderas korrekt.  
- **Resurskontroll:** Den inbyggda `IResourceSavingCallback` låter dig bestämma exakt var varje bild sparas, vilket eliminerar behovet av ett separat rensningssteg.

## Förutsättningar

- .NET 6.0 eller senare (kompatibel med .NET Framework 4.7+ också)  
- Aspose.Words för .NET (NuGet‑paket `Aspose.Words`)  
- Ett käll‑`Document`‑objekt (DOCX, PDF, RTF, osv.)  

Ingen extra bibliotek krävs; callback‑API:t är en del av Aspose.Words.

## Hur konverterar du docx till markdown? 

Läs in ditt källdokument med `new Document("source.docx")`, konfigurera `MarkdownSaveOptions` för att använda en callback som skriver varje bild till `md-resources/`, och anropa sedan `doc.Save("output.md", saveOptions)`. Detta trestegs‑mönster konverterar filen, extraherar bilder och producerar en ren markdown‑fil med relativa bildlänkar—allt i ett enda metodanrop.

### Steg 1: konfigurera sparalternativ för markdown‑konvertering

MarkdownSaveOptions konfigurerar hur Aspose.Words konverterar ett dokument till Markdown.

```csharp
// Step 1: Initialize Markdown save options
var markdownSaveOptions = new Aspose.Words.Saving.MarkdownSaveOptions();
```

```csharp
// Step 1: Initialize Markdown save options
var markdownSaveOptions = new Aspose.Words.Saving.MarkdownSaveOptions();
```

> **Varför detta är viktigt:**  
> Utan att explicit skapa `MarkdownSaveOptions` faller biblioteket tillbaka på standardinställningarna som bäddar in bilder direkt i Markdown‑filen som Base64‑strängar. Det gör filen enorm och motverkar syftet med en ren *images*-mapp.

### Steg 2: definiera en resurs‑sparande callback för att exportera bilder

`IResourceSavingCallback` låter dig styra var varje resurs (bild, SVG) sparas under export.

Nu talar vi om för spararen **var** varje bild ska placeras. `IResourceSavingCallback`‑gränssnittet ger oss en hook som triggas för varje resurs (bild, SVG, osv.) som upptäcks under exporten. Inuti callbacken:

1. Säkerställ att mål‑mappen finns (`md-resources/`).  
2. Sätt `OutputFileName` till mappen plus det ursprungliga resursnamnet.  

```csharp
// Step 2: Hook into the resource‑saving pipeline
markdownSaveOptions.ResourceSavingCallback = new Aspose.Words.Saving.IResourceSavingCallback(
    (args) =>
    {
        // All images will be placed in "md-resources" relative to the output .md file
        const string folder = "md-resources/";
        Directory.CreateDirectory(folder);          // Create folder if it doesn’t exist

        // Preserve the original file name (e.g., image001.png) but prepend the folder path
        args.OutputFileName = Path.Combine(folder, args.ResourceFileName);

        // Optional: you could also change the format here (e.g., convert BMP to PNG)
        // args.ResourceFileName = Path.ChangeExtension(args.ResourceFileName, ".png");
    });
```

> **Vanlig fråga:** *Vad händer om jag vill bädda in bilder istället för att spara dem?*  
> Hoppa bara över callbacken eller sätt `args.OutputFileName = null;` – spararen kommer automatiskt att bädda in bilden som en Base64‑sträng.

> **Edge case:** Vissa äldre dokument innehåller dubblett‑bildnamn. Callbacken ovan kommer att skriva över den tidigare filen. För att undvika det kan du lägga till ett GUID:

```csharp
args.OutputFileName = Path.Combine(folder,
    $"{Path.GetFileNameWithoutExtension(args.ResourceFileName)}_{Guid.NewGuid()}{Path.GetExtension(args.ResourceFileName)}");
```

### Steg 3: spara dokumentet som markdown och verifiera resultatet

Med alternativen fullt konfigurerade är det sista anropet en enradare som skriver Markdown‑filen och de associerade bilderna till disk.

```csharp
// Step 3: Perform the actual export
string outputPath = @"C:\Exports\MyReport.md";
doc.Save(outputPath, markdownSaveOptions);
```

Om allt går bra kommer du att se:

- `MyReport.md` – markdown‑representationen av ditt källdokument.  
- `md-resources/` – en mapp bredvid `.md`‑filen som innehåller varje extraherad bild (t.ex. `image001.png`, `image002.jpg`).  

**Exempel på markdown‑snutt** (automatiskt genererad av Aspose.Words):

```markdown
# Sample Report

Here is an introductory paragraph.

![Sample image](md-resources/image001.png)

More text follows...
```

[Sample image](md-resources/image001.png)

> **Proffstips:** Öppna den genererade `.md`‑filen i VS Code eller någon Markdown‑förhandsgranskare; bilderna bör visas omedelbart eftersom de relativa sökvägarna matchar mappstrukturen.

## Fullt körbart exempel (utan extra kodblock)

Nedan är ett självständigt konsolprogram som du kan klistra in i ett nytt .NET‑projekt och köra. Det skapar ett enkelt Word‑dokument, lägger till en bild och sedan **skapar markdown från dokumentet** samtidigt som bilden lagras i en undermapp.

```csharp
using System;
using System.IO;
using Aspose.Words;
using Aspose.Words.Saving;

class Program
{
    static void Main()
    {
        // 1️⃣ Create a sample Word document with an image
        var doc = new Document();
        var builder = new DocumentBuilder(doc);
        builder.Writeln("Hello, this is a test document.");
        builder.InsertImage("sample-image.png"); // Ensure this file exists next to exe

        // 2️⃣ Configure markdown export options (see Step 1 & 2 above)
        var markdownOptions = new MarkdownSaveOptions();
        markdownOptions.ResourceSavingCallback = new IResourceSavingCallback(
            (args) =>
            {
                const string folder = "md-resources/";
                Directory.CreateDirectory(folder);
                args.OutputFileName = Path.Combine(folder, args.ResourceFileName);
            });

        // 3️⃣ Save as markdown (Step 3)
        string outputFolder = Path.Combine(Environment.CurrentDirectory, "output");
        Directory.CreateDirectory(outputFolder);
        string markdownPath = Path.Combine(outputFolder, "ExportedDoc.md");
        doc.Save(markdownPath, markdownOptions);

        Console.WriteLine($"✅ Markdown saved to: {markdownPath}");
        Console.WriteLine("📂 Images saved in: md-resources/");
    }
}
```

**Vad du bör se** efter körning:

```
✅ Markdown saved to: C:\MyProject\output\ExportedDoc.md
📂 Images saved in: md-resources/
```

Öppna `ExportedDoc.md` – bildreferensen kommer att peka på `md-resources/sample-image.png`, och bilden kommer att visas korrekt i alla Markdown‑visare.

## Vanliga varianter

| Scenario | Hur man anpassar koden |
|----------|------------------------|
| **Hoppa över bildexport** (bädda in som Base64) | Utelämna `ResourceSavingCallback` helt, eller sätt `args.OutputFileName = null;` i callbacken. |
| **Ändra bildformat** (t.ex. alla PNG) | Inuti callbacken, ändra `args.ResourceFileName` och eventuellt konvertera strömmen innan skrivning. |
| **Anpassat mappnamn** | Ersätt `"md-resources/"` med någon relativ eller absolut sökväg du föredrar. |
| **Flera dokument i en batch** | Loopa över en samling av `Document`‑objekt, återanvänd samma `MarkdownSaveOptions`‑instans (se bara till att mappen rensas eller får ett unikt namn per körning). |

## Vanliga problem och lösningar

- **Bilder visas inte i markdown‑förhandsgranskaren** – Verifiera att den relativa sökvägen i markdown (`md-resources/image001.png`) matchar den faktiska mappplatsen relativt `.md`‑filen.  
- **Dubblett‑bildnamn orsakar överskrivningar** – Lägg till en unik identifierare (GUID eller inkrementell räknare) i callbacken för att garantera distinkta filnamn.  
- **Stora dokument orsakar minnespress** – Använd `Document.OptimizeResources()` före sparning; detta minskar minnesanvändning genom att frigöra oanvända strömmar.  
- **Ej stödda bildformat** – Aspose.Words stödjer PNG, JPEG, BMP, GIF och TIFF. Konvertera ej stödda format till ett av dessa innan du lägger till dem i källdokumentet.

## Vanliga frågor

**Q: Kan jag använda detta tillvägagångssätt i en ASP .NET Web API som returnerar en ZIP‑fil?**  
A: Ja. Generera markdown och bilder i en temporär mapp, lägg till dem i ett `ZipArchive` och strömma ZIP‑filen tillbaka till klienten. Samma `MarkdownSaveOptions` och callback fungerar oförändrat.

**Q: Bevarar konverteringen Word‑stilar som rubriker och tabeller?**  
A: Absolut. Aspose.Words mappar Word‑rubrikstilar till markdown `#`‑rubriker och konverterar tabeller till markdown‑pipe‑syntax, vilket bevarar cellinnehåll och justering.

**Q: Krävs en kommersiell licens för produktionsanvändning?**  
A: Ja. En gratis utvärderingslicens finns för testning, men produktionsdistributioner kräver en köpt Aspose.Words‑licens.

**Q: Hur hanterar biblioteket lösenordsskyddade dokument?**  
A: Läs in dokumentet med `new Document("file.docx", new LoadOptions { Password = "yourPassword" })` innan du anropar markdown‑sparrutinen.

**Q: Vilka .NET‑versioner stöds officiellt?**  
A: Aspose.Words stödjer .NET Framework 4.7+, .NET Core 3.1+, .NET 5, .NET 6 och senare.

- Använd `MarkdownSaveOptions` för fin‑granulär kontroll.
