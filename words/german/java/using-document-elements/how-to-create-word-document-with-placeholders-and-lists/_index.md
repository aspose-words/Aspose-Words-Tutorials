# Wie man ein Word‑Dokument mit Platzhaltern und Listen erstellt

Wenn Sie **ein Word‑Dokument** programmgesteuert **erstellen** müssen, zeigt Ihnen diese Anleitung genau, wie es geht. Wir gehen durch **Platzhalter‑Text setzen**, **Listeneinträge hinzufügen** und **wie man SDT** (Structured Document Tag)‑Steuerelemente mit Aspose.Words für .NET verwendet.

Entwickler fragen häufig nach einer Möglichkeit, Inhaltssteuerelemente — wie reine Text‑Platzhalter oder Dropdown‑Listen — direkt in eine .docx‑Datei einzubetten, ohne Word zu öffnen. Dieses Tutorial liefert ein vollständiges, ausführbares Beispiel, erklärt, warum jeder Schritt wichtig ist, und behandelt gängige Varianten wie das Hinzufügen der Steuerelemente zu einem bestehenden Dokument oder das Anpassen von Listeneinträgen.

## Voraussetzungen

Bevor Sie beginnen, stellen Sie sicher, dass Sie Folgendes haben:

- .NET 6.0 SDK oder neuer installiert  
- Visual Studio 2022 (oder eine beliebige C#‑IDE)  
- Eine aktive Aspose.Words für .NET‑Lizenz (eine kostenlose Testlizenz reicht für die Entwicklung)  
- Grundlegende Kenntnisse der C#‑Syntax  

Der Code richtet sich an **Aspose.Words 23.9** (die zum Zeitpunkt des Schreibens neueste stabile Version). Passen Sie die NuGet‑Paketversion an, falls Sie eine neuere Version verwenden.

Ein frisches `Document` zu erzeugen stellt sicher, dass Sie mit einer sauberen Dateistruktur beginnen und versteckte Formatierungen vermeiden, die beim Öffnen einer Vorlage auftreten können. `DocumentBuilder` abstrahiert die Low‑Level‑OPC‑ (Open Packaging Convention) Behandlung, sodass Sie sich auf den Inhalt konzentrieren können.

## Einen reinen Text‑Structured Document Tag einfügen (Platzhalter‑Text setzen)

Ein reiner Text‑SDT verhält sich wie ein Inhaltssteuerelement, das der Benutzer ausfüllen kann. Das Setzen von `Title` und `PlaceholderName` liefert einen freundlichen Hinweis innerhalb von Word.

```csharp
            // Step 2: Insert a plain‑text SDT and set its placeholder text
            StructuredDocumentTag plainTextTag = builder.InsertStructuredDocumentTag(
                StructuredDocumentTagType.PlainText, true);
            plainTextTag.Title = "CustomerName";
            plainTextTag.PlaceholderName = "Enter name";
```

**Erläuterung:**  
- `InsertStructuredDocumentTag` erstellt das Steuerelement an der aktuellen Cursor‑Position des Builders.  
- `StructuredDocumentTagType.PlainText` weist Word an, ein einfaches Textfeld darzustellen.  
- `Title` ist der interne Name, den Word‑XML verwendet; er ist praktisch für spätere Datenbindung.  
- `PlaceholderName` ist der graue Hinweis, der erscheint, bis der Benutzer etwas eingibt.

> **Pro‑Tipp:** Wenn der Platzhalter im *Eigenschaften*‑Paneel des Dokuments erscheinen soll, setzen Sie zusätzlich `plainTextTag.Tag = "CustomerName"`.

## Ein Dropdown‑Listen‑SDT einfügen (wie man sdt verwendet)

Eine Dropdown‑Liste ermöglicht es, eine vordefinierte Menge von Auswahlmöglichkeiten anzubieten. Dies ist der Kern von **wie man sdt verwendet** für aufzählbare Daten.

```csharp
            // Step 3: Insert a drop‑down list SDT and define its title
            StructuredDocumentTag dropdownTag = builder.InsertStructuredDocumentTag(
                StructuredDocumentTagType.DropDownList, true);
            dropdownTag.Title = "Country";
```

**Warum ein Dropdown?**  
Dropdown‑Listen verbessern die Datenkonsistenz und reduzieren Tippfehler. Die Eigenschaft `Title` dient erneut als Kennzeichen für nachgelagerte Verarbeitung (z. B. beim Extrahieren von Formulardaten).

## Listeneinträge zur Dropdown‑Liste hinzufügen (Listeneinträge hinzufügen)

Jetzt füllen wir das Steuerelement mit auswählbaren Werten. Jeder `ListItem` erhält einen Anzeigetext und optional einen Wert, der im XML des Dokuments gespeichert werden kann.

```csharp
            // Step 4: Populate the drop‑down with selectable items
            dropdownTag.ListItems.Add(new ListItem("USA", "US"));
            dropdownTag.ListItems.Add(new ListItem("Canada", "CA"));
            dropdownTag.ListItems.Add(new ListItem("Mexico", "MX"));
```

**Wichtige Punkte:**  

- Das erste Argument (`"USA"`) ist das, was der Benutzer sieht.  
- Das zweite Argument (`"US"`) ist der zugrunde liegende Wert, den Sie programmgesteuert auslesen können.  
- Sie können beliebig viele Einträge hinzufügen; die Liste wird in den `<w:listItem>`‑Elementen des .docx‑XML gespeichert.

### Sonderfälle und Varianten

| Situation | Empfohlene Anpassung |
|-----------|----------------------|
| **Steuerelemente zu einer bestehenden Datei hinzufügen** | Laden Sie die Datei mit `new Document("Existing.docx")` anstelle eines neuen `Document`. |
| **Platzhalter als Pflichtfeld festlegen** | Setzen Sie `plainTextTag.IsShowingPlaceholderWhenEmpty = false` bzw. `plainTextTag.IsShowingPlaceholderWhenEmpty = true` abhängig von Ihrer Validierungslogik. |
| **Listeneinträge an eine Datenquelle binden** | Durchlaufen Sie eine Sammlung (`foreach (var country in countries)`) und rufen Sie `dropdownTag.ListItems.Add(new ListItem(country.Name, country.Code))` auf. |
| **Steuerelement stylen** | Verwenden Sie `builder.Font`‑Eigenschaften vor dem Einfügen des SDT, um den Standardstil des Platzhalter‑Texts zu beeinflussen. |
| **Steuerelement später entfernen** | Finden Sie es über `doc.GetChildNodes(NodeType.StructuredDocumentTag, true)` und rufen Sie `tag.Remove();` auf. |

## Wie man Steuerelemente programmgesteuert erstellt – bewährte Vorgehensweisen

1. **Dokument zuerst erstellen** – das frühe Initialisieren von `DocumentBuilder` verhindert Überraschungen bei der Cursor‑Position.  
2. **Titel und Tags setzen** – sie fungieren als stabile Kennungen für spätere Datenauslese.  
3. **Platzhalter‑Text hinzufügen** – verbessert die Benutzererfahrung, besonders bei reinen Text‑Tags.  
4. **Listeneinträge sofort befüllen** – Word rendert das Dropdown korrekt nur, wenn die Liste bereits angehängt ist.  
5. **Einmal speichern** – wiederholte `Save`‑Aufrufe innerhalb einer Schleife erhöhen den I/O‑Overhead dramatisch.

Wenn Sie diese Schritte befolgen, stellen Sie sicher, dass die Word‑Datei sowohl *maschinenlesbar* (für Backend‑Verarbeitung) als auch *benutzerfreundlich* (für Front‑End‑Bearbeitung) ist.
