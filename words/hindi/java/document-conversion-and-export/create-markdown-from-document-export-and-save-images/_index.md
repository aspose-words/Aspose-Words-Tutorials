# docx को markdown में छवियों के साथ उपफ़ोल्डर में कैसे बदलें

यदि आपको **convert docx to markdown** करने की आवश्यकता है जबकि प्रत्येक एम्बेडेड चित्र को व्यवस्थित रूप से रखना है, तो आप सही जगह पर आए हैं। कई डेवलपर्स प्रोग्रामेटिक रूप से रिपोर्ट, मैनुअल या ब्लॉग ड्राफ्ट बनाते हैं और आउटपुट डायरेक्टरी में बिखरे हुए इमेज फ़ाइलों के अराजक मिश्रण का सामना करते हैं। यह ट्यूटोरियल Aspose.Words for .NET का उपयोग करके एक साफ़, कॉलबैक‑ड्रिवेन दृष्टिकोण दिखाता है जो दस्तावेज़ को markdown में एक्सपोर्ट करता है, प्रत्येक छवि को एक समर्पित *md‑resources* फ़ोल्डर में संग्रहीत करता है, और अंतिम markdown फ़ाइल को प्रकाशित करने के लिए तैयार सहेजता है।

> **त्वरित नज़र:**  
> • `MarkdownSaveOptions` सेट करें  
> • `IResourceSavingCallback` को लागू करें ताकि छवियों को पुनर्निर्देशित किया जा सके  
> • कॉन्फ़िगर किए गए विकल्पों के साथ `Document.Save` को कॉल करें  

अब जब आप समझ गए हैं कि पोस्ट‑प्रोसेसिंग की तुलना में कॉलबैक क्यों बेहतर है, चलिए चरण‑दर‑चरण समाधान में गहराई से देखते हैं।

- **convert docx to markdown वास्तव में क्या करता है?** यह Word‑processing मार्कअप को साधारण‑टेक्स्ट markdown में बदलता है जबकि हेडिंग्स, सूचियों, तालिकाओं और छवि संदर्भों को संरक्षित रखता है।  
- **कौन सा लाइब्रेरी रूपांतरण को संभालता है?** Aspose.Words for .NET एक पूरी तरह प्रबंधित, सर्वर‑साइड API प्रदान करता है जो Microsoft Word स्थापित किए बिना काम करता है।  
- **क्या मुझे कोई इमेज‑प्रोसेसिंग कोड लिखना पड़ेगा?** नहीं; `IResourceSavingCallback` प्रत्येक छवि को निर्दिष्ट फ़ोल्डर में सहेजने का ध्यान रखता है।

## convert docx to markdown क्या है?

**Convert docx to markdown** वह प्रक्रिया है जिसमें Microsoft Word दस्तावेज़ (DOCX) को लेकर markdown (`.md`) फ़ाइल बनाई जाती है जो समान सामग्री को markdown सिंटैक्स में दर्शाती है। रूपांतरण संरचनात्मक तत्वों को संरक्षित रखता है और वैकल्पिक रूप से एम्बेडेड संसाधनों जैसे छवियों को निकालता है।

रूपांतरण Aspose.Words द्वारा किया जाता है, एक लाइब्रेरी जो **35+ इनपुट और आउटपुट फॉर्मेट्स** का समर्थन करती है—जिसमें DOCX, PDF, HTML, और Markdown शामिल हैं—जिससे आप कई‑सौ‑पृष्ठों वाले दस्तावेज़ों को पूरी फ़ाइल को मेमोरी में लोड किए बिना संभाल सकते हैं।

## docx को markdown में कैसे बदलें? 

अपने स्रोत दस्तावेज़ को `new Document("source.docx")` से लोड करें, `MarkdownSaveOptions` को इस तरह कॉन्फ़िगर करें कि वह प्रत्येक छवि को `md-resources/` में लिखने वाला कॉलबैक उपयोग करे, और फिर `doc.Save("output.md", saveOptions)` को कॉल करें। यह तीन‑चरणीय पैटर्न फ़ाइल को बदलता है, छवियों को निकालता है, और सापेक्ष छवि लिंक के साथ एक साफ़ markdown फ़ाइल बनाता है—सभी एक ही मेथड कॉल में।

### चरण 1: markdown रूपांतरण के लिए सहेजने के विकल्प कॉन्फ़िगर करें

MarkdownSaveOptions यह निर्धारित करता है कि Aspose.Words दस्तावेज़ को Markdown में कैसे बदलता है।

```csharp
// Step 1: Initialize Markdown save options
var markdownSaveOptions = new Aspose.Words.Saving.MarkdownSaveOptions();
```

```csharp
// Step 1: Initialize Markdown save options
var markdownSaveOptions = new Aspose.Words.Saving.MarkdownSaveOptions();
```

> **यह क्यों महत्वपूर्ण है:**  
> बिना स्पष्ट रूप से `MarkdownSaveOptions` बनाए, लाइब्रेरी डिफ़ॉल्ट सेटिंग्स पर वापस आती है जो छवियों को सीधे Markdown फ़ाइल में Base64 स्ट्रिंग्स के रूप में एम्बेड करती हैं। इससे फ़ाइल बहुत बड़ी हो जाती है और साफ़ *images* फ़ोल्डर रखने के उद्देश्य को नष्ट कर देती है।

### चरण 2: छवियों को एक्सपोर्ट करने के लिए रिसोर्स‑सेविंग कॉलबैक परिभाषित करें

`IResourceSavingCallback` आपको निर्यात के दौरान प्रत्येक रिसोर्स (छवि, SVG) को कहाँ सहेजा जाए, यह नियंत्रित करने देता है।

अब हम सेव करने वाले को बताते हैं **कि** प्रत्येक छवि कहाँ रखी जाए। `IResourceSavingCallback` इंटरफ़ेस हमें एक हुक देता है जो निर्यात के दौरान पाए गए प्रत्येक रिसोर्स (छवि, SVG, आदि) के लिए फायर होता है। कॉलबैक के अंदर हम:

1. लक्ष्य फ़ोल्डर मौजूद है यह सुनिश्चित करें (`md-resources/`)।  
2. `OutputFileName` को फ़ोल्डर प्लस मूल रिसोर्स नाम पर सेट करें।  

```csharp
// Step 2: Hook into the resource‑saving pipeline
markdownSaveOptions.ResourceSavingCallback = new Aspose.Words.Saving.IResourceSavingCallback(
    (args) =>
    {
        // All images will be placed in "md-resources" relative to the output .md file
        const string folder = "md-resources/";
        Directory.CreateDirectory(folder);          // Create folder if it doesn’t exist

        // Preserve the original file name (e.g., image001.png) but prepend the folder path
        args.OutputFileName = Path.Combine(folder, args.ResourceFileName);

        // Optional: you could also change the format here (e.g., convert BMP to PNG)
        // args.ResourceFileName = Path.ChangeExtension(args.ResourceFileName, ".png");
    });
```

> **सामान्य प्रश्न:** *यदि मैं छवियों को सहेजने के बजाय एम्बेड करना चाहूँ तो क्या होगा?*  
> सिर्फ कॉलबैक को स्किप करें या `args.OutputFileName = null;` सेट करें – सेव करने वाला स्वचालित रूप से छवि को Base64 स्ट्रिंग के रूप में एम्बेड कर देगा।  

> **विशिष्ट मामला:** कुछ पुराने दस्तावेज़ों में डुप्लिकेट छवि नाम होते हैं। ऊपर दिया गया कॉलबैक पहले की फ़ाइल को ओवरराइट कर देगा। इसे रोकने के लिए, आप GUID जोड़ सकते हैं:  

```csharp
args.OutputFileName = Path.Combine(folder,
    $"{Path.GetFileNameWithoutExtension(args.ResourceFileName)}_{Guid.NewGuid()}{Path.GetExtension(args.ResourceFileName)}");
```

### चरण 3: दस्तावेज़ को markdown के रूप में सहेजें और आउटपुट सत्यापित करें

विकल्प पूरी तरह कॉन्फ़िगर हो जाने के बाद, अंतिम कॉल एक-लाइनर है जो Markdown फ़ाइल और संबंधित छवियों को डिस्क पर लिखता है।

```csharp
// Step 3: Perform the actual export
string outputPath = @"C:\Exports\MyReport.md";
doc.Save(outputPath, markdownSaveOptions);
```

यदि सब कुछ ठीक चलता है तो आप देखेंगे:

- `MyReport.md` – आपके स्रोत दस्तावेज़ का Markdown प्रतिनिधित्व।  
- `md-resources/` – `.md` फ़ाइल के बगल में एक फ़ोल्डर जिसमें प्रत्येक निकाली गई छवि होती है (जैसे, `image001.png`, `image002.jpg`).  

**उदाहरण markdown स्निपेट** (Aspose.Words द्वारा स्वचालित रूप से उत्पन्न):

```markdown
# Sample Report

Here is an introductory paragraph.

![Sample image](md-resources/image001.png)

More text follows...
```

[उदाहरण छवि](md-resources/image001.png)

> **प्रो टिप:** जेनरेट की गई `.md` फ़ाइल को VS Code या किसी भी Markdown प्रीव्यूअर में खोलें; छवियां तुरंत रेंडर होनी चाहिए क्योंकि सापेक्ष पाथ फ़ोल्डर संरचना से मेल खाते हैं।

## पूर्ण, चलाने योग्य उदाहरण (कोई अतिरिक्त कोड ब्लॉक नहीं)

नीचे एक स्व-निहित कंसोल प्रोग्राम है जिसे आप एक नए .NET प्रोजेक्ट में पेस्ट करके चला सकते हैं। यह एक सरल Word दस्तावेज़ बनाता है, एक छवि जोड़ता है, और फिर **creates markdown from document** करते हुए छवि को उपफ़ोल्डर में संग्रहीत करता है।

```csharp
using System;
using System.IO;
using Aspose.Words;
using Aspose.Words.Saving;

class Program
{
    static void Main()
    {
        // 1️⃣ Create a sample Word document with an image
        var doc = new Document();
        var builder = new DocumentBuilder(doc);
        builder.Writeln("Hello, this is a test document.");
        builder.InsertImage("sample-image.png"); // Ensure this file exists next to exe

        // 2️⃣ Configure markdown export options (see Step 1 & 2 above)
        var markdownOptions = new MarkdownSaveOptions();
        markdownOptions.ResourceSavingCallback = new IResourceSavingCallback(
            (args) =>
            {
                const string folder = "md-resources/";
                Directory.CreateDirectory(folder);
                args.OutputFileName = Path.Combine(folder, args.ResourceFileName);
            });

        // 3️⃣ Save as markdown (Step 3)
        string outputFolder = Path.Combine(Environment.CurrentDirectory, "output");
        Directory.CreateDirectory(outputFolder);
        string markdownPath = Path.Combine(outputFolder, "ExportedDoc.md");
        doc.Save(markdownPath, markdownOptions);

        Console.WriteLine($"✅ Markdown saved to: {markdownPath}");
        Console.WriteLine("📂 Images saved in: md-resources/");
    }
}
```

**चलाने के बाद आपको क्या दिखना चाहिए**:

```
✅ Markdown saved to: C:\MyProject\output\ExportedDoc.md
📂 Images saved in: md-resources/
```

`ExportedDoc.md` खोलें – छवि संदर्भ `md-resources/sample-image.png` की ओर इशारा करेगा, और चित्र किसी भी Markdown व्यूअर में सही ढंग से प्रदर्शित होगा।

## अक्सर पूछे जाने वाले विविधताएँ

| परिदृश्य | कोड को कैसे अनुकूलित करें |
|----------|----------------------|
| **छवि निर्यात को छोड़ें** (Base64 के रूप में एम्बेड) | `ResourceSavingCallback` को पूरी तरह छोड़ दें, या कॉलबैक के अंदर `args.OutputFileName = null;` सेट करें। |
| **छवि फ़ॉर्मेट बदलें** (जैसे, सभी PNG) | कॉलबैक के अंदर, `args.ResourceFileName` को संशोधित करें और वैकल्पिक रूप से लिखने से पहले स्ट्रीम को कनवर्ट करें। |
| **कस्टम फ़ोल्डर नाम** | `"md-resources/"` को किसी भी रिलेटिव या एब्सोल्यूट पाथ से बदलें जो आप पसंद करें। |
| **बैच में कई दस्तावेज़** | `Document` ऑब्जेक्ट्स के संग्रह पर लूप करें, वही `MarkdownSaveOptions` इंस्टेंस पुन: उपयोग करें (सिर्फ यह सुनिश्चित करें कि फ़ोल्डर को साफ़ किया गया है या प्रत्येक रन के लिए अद्वितीय नाम दिया गया है)। |

## सामान्य समस्याएँ और समाधान

- **छवियां markdown प्रीव्यू में नहीं दिख रही हैं** – सुनिश्चित करें कि markdown में सापेक्ष पाथ (`md-resources/image001.png`) वास्तविक फ़ोल्डर स्थान से मेल खाता है जो `.md` फ़ाइल के सापेक्ष है।  
- **डुप्लिकेट छवि नामों के कारण ओवरराइट** – कॉलबैक के अंदर एक अद्वितीय पहचानकर्ता (GUID या क्रमिक काउंटर) जोड़ें ताकि फ़ाइलनाम अलग रहें।  
- **बड़े दस्तावेज़ मेमोरी दबाव पैदा कर रहे हैं** – सहेजने से पहले `Document.OptimizeResources()` का उपयोग करें; यह अनउपयोगी स्ट्रीम्स को डिस्पोज़ करके मेमोरी उपयोग को कम करता है।  
- **असमर्थित छवि फ़ॉर्मेट** – Aspose.Words PNG, JPEG, BMP, GIF, और TIFF को समर्थन देता है। असमर्थित फ़ॉर्मेट को इनमें से किसी एक में बदलें फिर स्रोत दस्तावेज़ में जोड़ें।  

## अक्सर पूछे जाने वाले प्रश्न

**Q: क्या मैं इस दृष्टिकोण को ASP .NET Web API में उपयोग कर सकता हूँ जो ZIP फ़ाइल लौटाता है?**  
A: हाँ। एक अस्थायी फ़ोल्डर में markdown और छवियां बनाएं, उन्हें `ZipArchive` में जोड़ें, और ZIP को क्लाइंट को स्ट्रीम करें। वही `MarkdownSaveOptions` और कॉलबैक बिना बदलाव के काम करेंगे।

**Q: क्या रूपांतरण Word शैलियों जैसे हेडिंग्स और टेबल्स को संरक्षित रखता है?**  
A: बिल्कुल। Aspose.Words Word हेडिंग शैलियों को markdown `#` हेडिंग्स में मैप करता है और टेबल्स को markdown पाइप सिंटैक्स में बदलता है, सेल सामग्री और संरेखण को संरक्षित रखता है।

**Q: क्या उत्पादन उपयोग के लिए व्यावसायिक लाइसेंस आवश्यक है?**  
A: हाँ। परीक्षण के लिए एक मुफ्त मूल्यांकन लाइसेंस उपलब्ध है, लेकिन उत्पादन परिनियोजन के लिए Aspose.Words लाइसेंस खरीदना आवश्यक है।

**Q: लाइब्रेरी पासवर्ड‑सुरक्षित दस्तावेज़ों को कैसे संभालती है?**  
A: markdown सहेजने की प्रक्रिया को कॉल करने से पहले `new Document("file.docx", new LoadOptions { Password = "yourPassword" })` के साथ दस्तावेज़ लोड करें।

**Q: कौन से .NET संस्करण आधिकारिक रूप से समर्थित हैं?**  
A: Aspose.Words .NET Framework 4.7+, .NET Core 3.1+, .NET 5, .NET 6 और बाद के संस्करणों को समर्थन देता है।

## निष्कर्ष

हमने **docx को markdown में कैसे बदलें**, **दस्तावेज़ को markdown में एक्सपोर्ट करें**, और **छवियों को उपफ़ोल्डर में सहेजें** को एक साफ़, कॉलबैक‑ड्रिवेन पैटर्न का उपयोग करके दिखाया है। मुख्य बिंदु हैं:

- सूक्ष्म नियंत्रण के लिए `MarkdownSaveOptions` का उपयोग करें।  
- छवियों को एक समर्पित फ़ोल्डर में निर्देशित करने के लिए `IResourceSavingCallback` लागू करें, जिससे आपका markdown व्यवस्थित रहे।  
- वही तकनीक अन्य रिसोर्स प्रकारों (SVG, ऑडियो) के लिए भी काम करती है, बस `args.ResourceType` की जाँच करें।

अगले कदमों में हेडिंग शैलियों को कस्टमाइज़ करना, इस रूटीन को CI पाइपलाइन में एकीकृत करना, या इसे एक माइक्रोसर्विस के रूप में उजागर करना शामिल हो सकता है जो markdown और उसके संसाधनों वाली ZIP लौटाता है। निर्माण ब्लॉक्स अब आपके टूलबॉक्स में हैं, इसलिए आप दस्तावेज़‑से‑markdown पाइपलाइन को आत्मविश्वास के साथ ऑटोमेट कर सकते हैं।

क्या आपके पास और प्रश्न हैं या कोई ऐसा कोना मामला मिला जिसे हमने नहीं कवर किया? नीचे टिप्पणी छोड़ें, और कोडिंग का आनंद लें!
